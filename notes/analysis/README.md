# Analysis Output Directory

This directory contains analysis reports and documents generated by the Claude Code multi-role workflow system.

## Directory Structure

```
notes/analysis/
├── requirements/     # Business & requirements analysis (Analyst role)
├── architecture/     # Architecture designs and reviews (Architect role)
└── test-strategy/    # Test strategies and coverage analysis (Test Analyst role)
```

## Purpose

When using the role-based workflow system, analysts can **optionally save** their important findings to this directory for:
- Team collaboration and review
- Version control and historical tracking
- Documentation and knowledge sharing
- Reference for future work

## Usage

### Automatic Saving (Recommended Approach)

When you complete analysis with a role (Analyst, Architect, or Test Analyst), you can optionally save the results:

```bash
# After analyst completes analysis
> 请将此分析保存到 notes/analysis/requirements/order-matching-analysis.md

# After architect completes design
> 请将设计保存到 notes/analysis/architecture/stop-loss-design.md

# After test analyst completes test strategy
> 请将测试策略保存到 notes/analysis/test-strategy/clob-coverage-analysis.md
```

### Temporary Analysis

Not all analysis needs to be saved. For exploratory work or quick investigations, the analysis can remain in the conversation only:

```bash
> 使用analyst快速分析这个性能问题
# Results shown in conversation, not saved
```

## File Naming Conventions

Use descriptive names that indicate:
- **What** was analyzed: `order-matching-performance.md`
- **Date** (optional): `2025-01-15-liquidation-analysis.md`
- **Module/Component**: `clob-match-engine-refactor.md`

## Version Control

These files are part of the Hermes repository and should be:
- ✅ Committed to git when they contain important decisions or designs
- ✅ Reviewed by the team before major architectural changes
- ✅ Updated when requirements or designs change
- ❌ Not committed if they're temporary scratch work

## Integration with Roles

### Analyst → `requirements/`
Business analysts save:
- Requirement specifications
- Performance analysis reports
- User flow documentation
- Gap analysis between requirements and implementation

### Architect → `architecture/`
Architects save:
- System design documents
- Architecture Decision Records (ADRs)
- Refactoring plans
- Integration patterns

### Test Analyst → `test-strategy/`
Test analysts save:
- Test coverage analysis
- Test strategy documents
- Edge case identification
- Regression test plans

## Benefits

1. **Knowledge Preservation**: Important decisions and analysis are documented
2. **Team Alignment**: Everyone can review and understand the reasoning
3. **Onboarding**: New team members can read historical analysis
4. **Audit Trail**: Track how and why decisions were made
5. **Reusability**: Reference previous analysis for similar work

## Clean-up

Periodically review this directory and:
- Archive outdated analysis to `notes/archive/`
- Remove temporary or obsolete documents
- Update living documents when designs change
- Consolidate related documents
